**This is a release candidate for 2.0.0.** It is published as a prerelease so the packages can be tried before the final version; the API is not expected to change. Please report any problem as an [issue](https://github.com/saveriogiostra/EndOfDayTime/issues).

Install it by naming the version explicitly, for example:

```
dotnet add package EndOfDayTime.Core --version 2.0.0-rc.1
```

2.0.0 fixes the handling of `00:00`, which the UI controls used to treat as "empty", and cleans up the parts of the API that could not be fixed without breaking changes.

**This release has breaking changes.** See [Upgrading from 1.0.0](https://github.com/saveriogiostra/EndOfDayTime/blob/v2.0.0-rc.1/CHANGELOG.md#upgrading-from-100) for what to change in your code.

## Breaking changes

**All UI controls: `00:00` is a real value, `null` means empty**
- WinForms, WPF, WebForms: `TimeValue` is `EndOfDayTime?`. In WinForms and WPF, `TimeValueChanged` carries `EndOfDayTime?` too.
- Blazor: `EndOfDayTimeInput` is now `EndOfDayTimeInput<TValue>`, with `TValue` either `EndOfDayTime` or `EndOfDayTime?`.
- ASP.NET Core: `EndOfDayTimeInputFor` and `EndOfDayTimeInput` accept nullable values, and `00:00` is rendered as `00:00` instead of an empty field.

**WinForms / WPF**
- An empty field is valid unless the new `IsRequired` property is set.
- `TimeValue` is `null` while the text is incomplete or invalid, instead of keeping the last valid value.

**WebForms**
- `EndOfDayTimeTextBox` derives from `TextBox`; `InputCssClass` is removed, use `CssClass`.
- Invalid posted text is kept in `Text` for correction.
- The `net8.0` target is removed; the package ships `lib/net48` only.

**ASP.NET Core**
- `EndOfDayTimeInputTagHelper` has a parameterless constructor.
- `BuildEndOfDayTimeInput` is no longer public.

**Core**
- `EndOfDayTime` is serialized to JSON as `"HH:mm"` without registering the converter. Non-string tokens throw `JsonException`.
- `TryParse` and `Parse` accept exactly `HH:mm` with ASCII digits; inputs such as `+5:30` are rejected.

## Added

- Core: `net8.0` target, with no `System.Text.Json` dependency and with `TimeOnly` conversions (`ToTimeOnly()`, `FromTimeOnly()`, explicit operators).
- Entity Framework Core: `UseEndOfDayTime()` for `ConfigureConventions`, and a `HasEndOfDayTimeConverter()` overload for `EndOfDayTime?` properties.
- WinForms / WPF: `IsRequired` on the control, and on `EndOfDayTimeValidationRule` in WPF.
- WebForms: the standard `TextBox` members (`CssClass`, `Enabled`, `Width`, `AutoPostBack`, ...) work on the control.

## Fixed

- Entity Framework Core: `ApplyEndOfDayTimeConverter()` failed to build the model on relational providers.
- ASP.NET Core: `endofdaytime-input.js` was missing from the package.
- WPF: `TimeValueChanged` was not raised when typing; `EndOfDayTimeConverter.ConvertBack` wrote `00:00` for unparseable text; updating `TimeValue` from user input replaced a binding on the property.
- WinForms / WPF: validation on lost focus also runs when the field is empty.
- Entity Framework Core, Blazor: the minimum dependency version is `8.0.0` rather than whichever 8.0.x patch was current at build time.

## Packages

All seven packages are released together as 2.0.0-rc.1: `EndOfDayTime.Core`, `EndOfDayTime.AspNet`, `EndOfDayTime.Blazor`, `EndOfDayTime.EntityFramework`, `EndOfDayTime.WebForms`, `EndOfDayTime.WinForms`, `EndOfDayTime.Wpf`.
